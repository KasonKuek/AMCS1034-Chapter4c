When things go wrong: exception handling

An exception is an error that happens while the program is running, such as dividing by zero or typing letters where a number is expected. Without handling, the program crashes. With try / except, the program catches the problem, reacts politely and keeps going.

Daily-life picture: you try to pay with your card. If it fails (except), you pay with cash. If it works (else), you collect your receipt. Either way (finally), you take your card back from the machine.

try

try:
  • The risky code
  • Stops at the first error
  • "Let me attempt this"

except

except ValueError:
  • Runs only if that error happens
  • Can have many
  • "Plan B"

else

else:
  • Runs only if no error
  • Optional
  • "It worked, carry on"

finally

finally:
  • Runs always
  • For clean-up (close files)
  • "Take your card back"

The full structure

try:
    # risky code
except ZeroDivisionError:
    # runs if this error happens
except (ValueError, TypeError) as e:
    # one block for several errors; e holds the message
except Exception:
    # catch-all, always put it LAST
else:
    # runs only if try had NO error
finally:
    # runs every time

Syntax error vs exception: a SyntaxError (missing colon, wrong indentation) stops Python before the program starts, so try cannot catch it. Exceptions happen during the run and can be caught.

raise: create your own error

Sometimes Python thinks the data is fine but your program doesn't, like an age of -5. Use raise to signal the problem yourself:

if age < 0:
    raise ValueError("age cannot be negative")

You can also make your own exception type: class InsufficientFundsError(Exception): pass.

How to read a traceback

  1. Read the last line first: it names the error and gives the message, e.g. ZeroDivisionError: division by zero.
  2. Look just above it for the line number where it happened.
  3. Ask: which value was wrong at that line? Fix the cause, or wrap it in try if bad input is expected.
